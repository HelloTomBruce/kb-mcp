## 0. 摘要

v0.8 的核心命题是把"个人工具"升级为"团队基础设施"，通过 **7 个高杠杆特性**补齐当前版本在并发、自动化、知识图谱利用、运维负担四个维度的短板：

| 类别 | 特性 | 目标 |
|---|---|---|
| 稳定性 | 异步化嵌入 | 消除 `kb add/update` 的同步 HTTP 阻塞 |
| 稳定性 | Inter-process 写锁 | 多进程并发写不再随机失败 |
| 稳定性 | Inotify/FSEvents watcher | watcher CPU 从每秒轮询降到事件驱动 |
| 智能化 | 内容级反向链接 | 自动从 body 抽取引用入图 |
| 智能化 | 多跳 RAG | 搜索结果自动扩展 1 跳邻居 |
| 智能化 | 类型化关系词典 | 关系有语义（影响分析、决策追溯） |
| 自动化 | 内置定时任务 | auto-commit / auto-embed / auto-reindex 零运维 |

**预计开发周期**: 10-15 周
**预计分版本**: 3 个小版本（v0.8.0 → v0.8.1 → v0.8.2）
**红线**: 严格遵守 `CLAUDE.md` 约束（未经用户主动要求禁止提交代码），所有改动由用户决定合并时机

## 1. 目标与非目标

### 1.1 目标 (v0.8 必须达成)

1. **零运维沉淀**：用户装上后不再需要手动跑 `embed / reindex / commit`，全部后台自动
2. **图谱驱动检索**：搜索结果携带 1 跳邻居，AI 拿到"决策 + 依据 + 关联"完整 context
3. **进程间协作**：MCP server、watcher、CLI 可同时运行不冲突
4. **关系可表达**：用户能用 `supersedes / depends-on / governs` 等语义化关系描述文档脉络
5. **可观测性**：embedding 队列、watcher 状态、定时任务都有可查询接口

### 1.2 非目标 (v0.8 不做)

- ❌ 多用户/权限模型（推迟到 v0.9）
- ❌ 加密 at rest（推迟到 v0.10）
- ❌ 实时协作（Y.js / OT，与 Git 同步哲学冲突）
- ❌ 移动端 App
- ❌ Web 端的图谱可视化编辑器（只读视图已有）
- ❌ 与 Notion / Linear / GitHub Issues 的 connector 集成

## 3. 七大特性详细设计

### 3.1 异步化嵌入计算

#### 3.1.1 当前痛点

```python
# store/sqlite.py 当前实现
def add(self, doc: Document) -> str:
    with self._txn() as cur:
        cur.execute("INSERT INTO documents ...")
        # ... FTS 同步 ...
        if self._embedder and self._embedder.enabled:
            self._index_embedding(cur, doc.id, doc.title + "\n" + doc.body)
            # ↑ 同步 HTTP 调用，Ollama 冷启动可达 30s
```

**问题**：
- 嵌入服务慢/挂时，`kb add` 直接卡住
- 失败被 silently 吞掉，文档无向量但 `kb_search(mode='semantic')` 永远不会返回它
- 重启后 `docs_vec` 不一致

#### 3.1.2 设计

引入 **embedding 任务队列**（migration 0007）：

```sql
CREATE TABLE embedding_queue (
    doc_id          TEXT PRIMARY KEY REFERENCES documents(id) ON DELETE CASCADE,
    enqueued_at     TEXT NOT NULL,
    attempts        INTEGER NOT NULL DEFAULT 0,
    max_attempts    INTEGER NOT NULL DEFAULT 5,
    last_error      TEXT,
    last_attempt_at TEXT,
    state           TEXT NOT NULL DEFAULT 'pending'  -- pending | in_progress | done | failed
);
CREATE INDEX idx_embedding_queue_state ON embedding_queue(state, enqueued_at);
```

**状态机**：

```
       enqueue
         ↓
      pending ────→ (worker picks) ────→ in_progress
                                            │
                          success           │          fail
                            ↓              │            ↓
                           done ←───────────┴───→ (attempts < 5 ? pending : failed)
```

**Worker 启动时机**：
- `kb serve` 启动 MCP server 时
- `kb admin start` 启动 Web 时
- `kb watch` 启动 watcher 时
- 任何 `SqliteStore` 实例化时（如果 `auto_start_worker=True`，默认开）

**Worker 实现**：

```python
# embedding/worker.py
class EmbeddingWorker:
    def __init__(self, store: SqliteStore, batch_size: int = 10):
        self.store = store
        self.batch_size = batch_size
        self._stop = threading.Event()
        self._thread: Optional[threading.Thread] = None

    def start(self) -> None:
        if self._thread and self._thread.is_alive():
            return
        self._stop.clear()
        self._thread = threading.Thread(
            target=self._run, name="kb-embedding-worker", daemon=True
        )
        self._thread.start()

    def stop(self, timeout: float = 5.0) -> None:
        self._stop.set()
        if self._thread:
            self._thread.join(timeout=timeout)

    def _run(self) -> None:
        # Worker 用独立 SqliteStore 实例（独立 connection）
        worker_store = SqliteStore(self.store.path, readonly=False)
        try:
            while not self._stop.is_set():
                processed = self.process_batch(worker_store)
                if processed == 0:
                    self._stop.wait(timeout=5.0)  # 空闲 5s 后再查
        finally:
            worker_store.close()
```

**重试策略**：
- 指数退避：1s, 5s, 30s, 5m, 30m（5 次）
- `max_attempts` 默认 5，可通过 config 调整
- `failed` 状态的文档可手动 `kb embed retry <doc-id>` 重置

#### 3.1.3 API 设计

**Store 层**：
```python
class SqliteStore:
    def enqueue_embedding(self, doc_id: str) -> None: ...
    def process_embedding_queue(self, batch_size: int = 10) -> int: ...
    def embedding_queue_status(self) -> EmbeddingQueueStatus: ...
    def reset_failed_embedding(self, doc_id: str) -> None: ...
```

**MCP 工具**（新增）：
- `kb_embed_status()` — 队列状态总览
- `kb_embed_retry(doc_id?)` — 重试 failed 项（不传则全部）

**CLI**：
```bash
kb embed status              # 显示 pending/in_progress/done/failed 计数
kb embed retry <doc-id>      # 重置单项
kb embed retry --all         # 重置全部 failed
```

#### 3.1.4 数据迁移

- **migration 0007**: 创建 `embedding_queue` 表
- **backfill**: 现有 `docs_vec` 已有向量的文档不入队；缺失向量的文档**不自动入队**（用户显式 `kb embed --rebuild` 才入队）
- **删表兼容性**：`prune` 操作时 `embedding_queue` 走 FK CASCADE 自动清理

#### 3.1.5 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Worker 线程与主线程争抢 connection | 高 | 中 | Worker 用独立 SqliteStore 实例（独立 connection） |
| Embedding 服务长期挂导致队列堆积 | 中 | 中 | max_attempts=5 强制上限；`kb embed status` 监控 |
| 多进程起多个 worker 重复处理 | 中 | 中 | 用 #2 的写锁保证"同一时间只有一个 worker 拉取 batch" |
| 队列与 FTS 同步触发器互相干扰 | 低 | 高 | embedding_queue 不参与 FTS，纯独立表 |
| dim 切换时 worker 触发全表重建 | 中 | 高 | worker 调用 `_vec_conn_lazy` 已实现降级，但要写入 `audit_log` 记录 |

### 3.2 Inter-process 写锁

#### 3.2.1 当前痛点

```
Process A: kb watch          Process B: kb serve (MCP)
  ↓                            ↓
SqliteStore.add()             SqliteStore.update()
  ↓                            ↓
BEGIN; INSERT;                 BEGIN; UPDATE;
  ↓                            ↓
SQLITE_BUSY (lock)            SQLITE_BUSY (lock)
  ↓                            ↓
silent failure                silent failure
```

**现状**：依赖 SQLite 自带 `busy_timeout=5s`，失败时返回模糊错误。

#### 3.2.2 设计

**双层防御**：

**层 1（基线）**：SQLite `PRAGMA busy_timeout = 5000` + `BEGIN IMMEDIATE`
- 已部分实现，扩展到所有 `_txn()` 入口
- 默认开，零依赖

**层 2（可选）**：fcntl/flock 文件锁
- `kb --strict-lock` 全局开关
- 锁文件 `<db_path>.lock`
- `acquire(timeout=10s)` 阻塞；超时抛 `ResourceBusyError`
- 跨平台：Linux fcntl、macOS flock、Windows msvcrt.locking

```python
# concurrency/write_lock.py
class WriteLock:
    def __init__(self, db_path: Path, timeout: float = 10.0):
        self.lock_path = db_path.with_suffix(db_path.suffix + ".lock")
        self.timeout = timeout
        self._fd: Optional[int] = None

    def __enter__(self) -> "WriteLock":
        self._fd = os.open(str(self.lock_path), os.O_CREAT | os.O_RDWR, 0o644)
        deadline = time.time() + self.timeout
        while True:
            try:
                if self._try_acquire():
                    return self
            except OSError:
                pass
            if time.time() >= deadline:
                self._release()
                raise ResourceBusyError(
                    f"another process is writing to {self.lock_path}; "
                    f"wait {self.timeout}s or check the holder"
                )
            time.sleep(0.1)

    def __exit__(self, *args) -> None:
        self._release()

    def _try_acquire(self) -> bool:
        # Linux: fcntl.flock(self._fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
        # macOS: 同上
        # Windows: msvcrt.locking(self._fd, msvcrt.LK_NBLCK, 1)
        ...
```


#### 3.2.4 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 进程崩溃未释放锁文件 | 中 | 中 | 启动时检测陈旧锁（>30s 无心跳）自动清理 |

| 用户多开 5+ 进程 | 低 | 低 | 文档化"建议进程数 ≤ 3" |

### 3.3 Inotify/FSEvents 替代轮询 watcher

#### 3.3.1 当前痛点

```python
# watcher.py:191
while self._running:
    res = self.scan_once()  # os.walk 全目录
    time.sleep(interval_seconds)  # 默认 1s
```

**问题**：
- 1k 文件目录 = 每秒 1 次全量 `os.walk` + `stat`
- 改动检测延迟 1-2s
- CPU 占用与文件数线性相关

#### 3.3.2 设计

**依赖**：`watchfiles >= 0.21`（Rust 实现，跨平台）

```python
# watcher/event_watcher.py
from watchfiles import awatch, Change, DefaultFilter

class EventWatcher(VaultWatcher):
    def run_event_based(self, debounce_ms: int = 200) -> None:
        async def _watch():
            async for changes in awatch(
                self.watch_dir,
                step=50,                          # batch 50ms
                debounce=debounce_ms,
                recursive=True,
                ignore_patterns=[".git/*", ".*"],
            ):
                self._handle_changes(changes)

        asyncio.run(_watch())

    def _handle_changes(self, changes: set[tuple[Change, str]]) -> None:
        # 复用 scan_once 的 _sync_file 逻辑
        for change_type, path_str in changes:
            path = Path(path_str)
            if change_type == Change.deleted:
                self._handle_delete(path)
            elif change_type == Change.added:
                self._handle_create(path)
            elif change_type == Change.modified:
                self._handle_modify(path)
```

**API 兼容**：

```python
class VaultWatcher:
    def run(
        self,
        mode: Literal["event", "poll"] = "event",  # 默认 event
        debounce_ms: int = 200,
        **kwargs
    ) -> None:
        if mode == "event" and WATCHFILES_AVAILABLE:
            self.run_event_based(debounce_ms=debounce_ms)
        else:
            logger.warning("Falling back to poll-based watcher")
            self.run_poll_based(interval_seconds=kwargs.get("interval", 1.0))
```

**降级**：
- `watchfiles` 不可用 → 自动 `mode="poll"`
- 启动时打印提示：`pip install watchfiles` 启用事件驱动

**Docker 注意事项**：
- 文档化：Docker bind mount 时 `inotify` 可能不工作，需挂载 `:cached` 或用 poll 模式
- `mode` 自动检测：检测到 `/proc/1/cgroup` 含 `docker` → 默认 poll

#### 3.3.3 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| `watchfiles` wheel 不覆盖 exotic 平台 | 低 | 中 | graceful 降级到 poll |
| 大量文件快速创建导致事件丢失 | 低 | 中 | `step=50ms` 批处理 + 全量 re-scan 兜底（每 5min 一次） |
| 编辑器 "保存 = 删 + 重建" 模式 | 中 | 低 | 监听 `Change.added` 也触发 update 路径而非 create |
| 跨平台事件行为差异（macOS FSEvents 不可靠的某些场景） | 中 | 中 | 每 60s 一次 mtime 兜底扫描 |

### 3.4 内容级反向链接

#### 3.4.1 当前痛点

```markdown
---
type: decision
title: Use SQLite FTS5
links:
  - to: lesson/dont-mix-sqlite-libs
    rel: relates-to
---

# Use SQLite FTS5

For full-text search, we adopt FTS5 (see [lesson on pysqlite3](lesson/dont-mix-sqlite-libs)).
This decision supersedes `dec/use-lucene` from the v0.1 prototype.
```

**问题**：
- Markdown 链接 `[text](lesson/dont-mix-sqlite-libs)` 不入图
- 反引号 ID `` `dec/use-lucene` `` 不入图
- 团队成员写文档要手动维护 `links:` 数组

#### 3.4.2 设计

**支持 3 种引用语法**：

| 语法 | 例子 | 解析为 |
|---|---|---|
| 显式 ID | `` `dec/use-sqlite-fts5` `` | `dec/use-sqlite-fts5` |
| Markdown 链接 | `[text](lesson/sqlite-libs)` | `lesson/sqlite-libs` |
| 裸 ID | 文本中的 `dec/use-vec0`（不在链接/反引号内） | `dec/use-vec0`（保守策略：仅在显式语境识别） |

**保守原则**：
- 仅解析符合 `^[a-z0-9][a-z0-9/_-]*$` 的候选 ID
- 必须在"已知 doc-id 集合"中（启动时加载）才入图
- 代码块 ``` 内的不解析

**解析器实现**：

```python
# watcher/parser.py
import re

# 三种 pattern，按优先级匹配
LINK_PATTERN = re.compile(r'\[([^\]]*)\]\(([a-z0-9][a-z0-9/_-]*)\)')
CODE_REF_PATTERN = re.compile(r'`([a-z0-9][a-z0-9/_-]*)`')
# 裸 ID 不实现（误识别风险太高）

def extract_body_references(
    body: str,
    known_ids: set[str],
) -> list[tuple[str, str]]:
    """返回 [(reference, syntax), ...]"""
    # 1. 移除代码块
    body_no_code = re.sub(r'```.*?```', '', body, flags=re.DOTALL)
    body_no_code = re.sub(r'`[^`]+`', '', body_no_code)  # 移除行内 code

    refs = []
    # 2. Markdown 链接
    for m in LINK_PATTERN.finditer(body):
        target = m.group(2)
        if target in known_ids:
            refs.append((target, "markdown"))
    # 3. 反引号引用（仅在已知 ID 集合中）
    for m in CODE_REF_PATTERN.finditer(body):
        target = m.group(1)
        if target in known_ids and target not in [r[0] for r in refs]:
            refs.append((target, "code"))
    return refs
```

**存储模型**：
- **不新建表**——直接复用 `links(from_id, to_id, rel)`
- 关系类型统一为 `"references"`（与 `relates-to` 区分）
- 写时同步：`SqliteStore.add/update` 在 frontmatter `links` 之外，自动添加 `references` 链接

**配置开关**：


#### 3.4.4 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|

### 3.5 多跳 RAG（Graph-Enhanced Retrieval）

#### 3.5.1 当前痛点

```python
# 当前 search 返回
results = store.search("SQLite FTS5", limit=10)
# → [dec/use-sqlite-fts5, api/fts5-tokenizer, lesson/dont-mix-sqlite-libs]
# AI 拿到 3 个孤立文档，不知道：
#   - use-sqlite-fts5 决策的"前因"（lesson/dont-mix-sqlite-libs）
#   - use-sqlite-fts5 决策的"后果"（api/fts5-tokenizer 是它的实现）
```

#### 3.5.2 设计

**核心思路**：在 `search()` 末尾，对 top-K hits 各自做 1 跳 BFS，把邻居节点作为 `related` 字段附加到响应。

**响应结构变化**：

```python
# schema.py 新增
class RelatedDoc(BaseModel):
    doc: Document
    rel: str
    direction: Literal["outbound", "inbound"]
    hop: int  # v0.8 固定 1

class SearchHit(BaseModel):
    doc: Document
    snippet: str
    score: float
    related: list[RelatedDoc] = []  # 新增
```

**打分模型**：

```python
def compute_related_score(parent_score: float, decay: float = 0.6) -> float:
    return parent_score * decay
```

**BFS 边界**：
- 1 跳（不做递归）
- 每个 hit 最多展开 `max_neighbors=5` 个邻居
- 邻居的 `body` 截断到 `neighbor_snippet_chars=200`

**整合到 search**：

```python
class SqliteStore:
    def search(
        self,
        query: str,
        *,
        mode: str = "hybrid",
        limit: int = 20,
        type: str | None = None,
        tags: list[str] | None = None,
        expand_graph: bool = True,         # 新增
        max_neighbors: int = 5,            # 新增
        decay: float = 0.6,                 # 新增
    ) -> list[SearchHit]:
        hits = self._search_impl(query, mode, limit, type, tags)
        if expand_graph and hits:
            hits = self._expand_with_graph(hits, max_neighbors, decay)
        return hits
```

**性能预算**：
- top-10 hits × 2 次 SQL（outbound + inbound）= 20 次查询
- 单次查询 <5ms，整体 +100ms
- 可选缓存：相同 query 1 分钟内复用

```python
# schedule/scheduler.py
class ScheduledTask(Protocol):
    name: str
    description: str
    def run(self, store: SqliteStore, config: dict) -> None: ...

TASK_REGISTRY: dict[str, type[ScheduledTask]] = {}

def register_task(name: str):
    def decorator(cls: type[ScheduledTask]) -> type[ScheduledTask]:
        TASK_REGISTRY[name] = cls
        return cls
    return decorator

@register_task("auto-commit")
class AutoCommitTask(ScheduledTask):
    name = "auto-commit"
    description = "导出变更并 git commit"
    def run(self, store, config):
        from kb_mcp_lite.vault import VaultManager
        vm = VaultManager()
        name = vm.get_current()
        vm.commit(config.get("message", "auto-commit"), name=name)
```

**调度器实现**：

```python
from apscheduler.schedulers.background import BackgroundScheduler

class TaskScheduler:
    def __init__(self, store: SqliteStore, config: dict):
        self.store = store
        self.config = config
        self.scheduler = BackgroundScheduler(daemon=True)
        self._job_history: list[JobRun] = []

    def start(self) -> None:
        for task_config in self.config.get("kb", {}).get("schedule", []):
            self._register(task_config)
        self.scheduler.start()

    def stop(self) -> None:
        self.scheduler.shutdown(wait=True)

    def _register(self, task_config: dict) -> None:
        task_name = task_config["task"]
        if task_name not in TASK_REGISTRY:
            logger.warning(f"Unknown task: {task_name}")
            return
        task_cls = TASK_REGISTRY[task_name]
        trigger = self._build_trigger(task_config)
        self.scheduler.add_job(
            func=self._run_task,
            trigger=trigger,
            args=[task_cls, task_config],
            id=f"{task_name}-{id(task_config)}",
            max_instances=1,  # 防止并发
            coalesce=True,
        )

    def _run_task(self, task_cls, task_config) -> None:
        # 用 write_lock 防止多进程同时跑
        try:
            with self.store.write_lock(timeout=30):
                task_instance = task_cls()
                start = time.time()
                task_instance.run(self.store, task_config)
                self._record(task_cls.name, "ok", time.time() - start)
        except Exception as e:
            self._record(task_cls.name, "error", 0, str(e))
            logger.exception(f"Scheduled task {task_cls.name} failed")
```

**进程模型**：

| 模式 | 启动 | 适用 |
|---|---|---|
| 嵌入式 | `kb serve` / `kb admin` 启动时自动起 | 单一进程多 vault |
| 守护进程 | `kb scheduler start --daemon` | 多 vault 共享 |
| 手动触发 | `kb scheduler run <task_name>` | 调试 |

**跨进程防重**：
- 复用 #2 的 `WriteLock`
- 同一任务在另一个进程跑时，本进程跳过本次触发

### 9.1 完整 SQL DDL

```sql
-- migration 0007_embedding_queue.sql
CREATE TABLE IF NOT EXISTS embedding_queue (
    doc_id          TEXT PRIMARY KEY REFERENCES documents(id) ON DELETE CASCADE,
    enqueued_at     TEXT NOT NULL,
    attempts        INTEGER NOT NULL DEFAULT 0,
    max_attempts    INTEGER NOT NULL DEFAULT 5,
    last_error      TEXT,
    last_attempt_at TEXT,
    state           TEXT NOT NULL DEFAULT 'pending'
        CHECK(state IN ('pending', 'in_progress', 'done', 'failed'))
);
CREATE INDEX IF NOT EXISTS idx_embedding_queue_state
    ON embedding_queue(state, enqueued_at);
CREATE INDEX IF NOT EXISTS idx_embedding_queue_failed
    ON embedding_queue(last_attempt_at) WHERE state = 'failed';

-- migration 0008_schedule_history.sql
CREATE TABLE IF NOT EXISTS schedule_history (
    run_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    task_name     TEXT NOT NULL,
    started_at    TEXT NOT NULL,
    finished_at   TEXT,
    status        TEXT NOT NULL CHECK(status IN ('ok', 'error', 'skipped')),
    duration_ms   INTEGER,
    error         TEXT,
    triggered_by  TEXT  -- 'cron' | 'interval' | 'manual' | 'auto'
);
CREATE INDEX IF NOT EXISTS idx_schedule_history_task
    ON schedule_history(task_name, started_at DESC);
CREATE INDEX IF NOT EXISTS idx_schedule_history_recent
    ON schedule_history(started_at DESC) WHERE status = 'error';
```
